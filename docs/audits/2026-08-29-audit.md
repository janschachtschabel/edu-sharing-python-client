# Audit — edu-sharing-python-client

Date: 2026-08-29 · Depth: **Standard** (all 12 dimensions, with line-by-line
reading of transport, auth, urls, agent/safety, extraction and the three service
clients) · Scope: the hand-written layer, 11,136 lines. The generated layer
(`src/edusharing/_generated`, 1131 files) is machine output and out of scope.

Predecessor: [2026-08-28](2026-08-28-audit.md), whose 16 findings are closed.
Added since: the examples as test cases, the import surface tidied, the b-api's
forwarded OpenAI routes, the metadata agent — and the first run against the
**production instance**.

---

## 1. Executive summary

The library itself is in good shape: 1020 offline tests at 99 % coverage of the
hand-written layer, no known vulnerability across 48 dependencies, no swallowed
exception, no unprotected path interpolation, and the central claim
"repository-agnostic" is now **measured** rather than asserted — the same suite
runs against staging and production.

The three largest risks are not in the code but around it. **First: CI has never
run** — there is no remote, and the pipeline is an unverified claim. **Second:
two breaking changes landed today with no changelog** (`BildungsAPI` now requires
an address; `call()` validates its route), at `version = "0.0.0"` and unpublished.
**Third: the architecture document is stale** — it knows neither the metadata
agent nor the b-api extension, and reports yesterday's test counts.

The single most important action: **set a remote and let CI run once.**
Everything else here is either small or already demonstrably sound; a pipeline
that has never executed is the one assurance in this project nobody has checked.

## 4. Verdict

**Conditional.**

The code holds. What is missing is the path to a user: CI has never shown that
the project builds on a foreign machine; two breaking changes from today are
recorded nowhere; and the architecture document describes yesterday.

**Conditions:**

1. Set a remote, see CI green once (F1)
2. Add a CHANGELOG with the two breaking changes (F2)
3. Bring ARCHITECTURE up to date (F3)

None of these concerns the library's correctness. All three concern whether a
third party can trust it.

## 5. Findings

### F1 🟠 Deployment — CI has never run

```
File:    .github/workflows/ci.yml
Problem: The pipeline (ruff + pytest over a Python matrix) exists, but the
         repository has no remote -- `git remote -v` is empty across 108
         commits, none of them ever pushed.
Why:     A pipeline that never ran is an unverified claim. It can fail on a
         Python version, a missing step or a dependency, and nobody would know.
Impact:  The first outside user is the first test of the build path.
Fix:     Set a remote, push once, read the result.
```

### F2 🟠 API — two breaking changes without a changelog

```
File:    src/edusharing/bapi/client.py:93 · src/edusharing/bapi/passthrough.py:146
Problem: Two signatures were tightened on 28./29.08.: `BildungsAPI` now requires
         `base_url` (previously defaulted), and `call()` rejects routes carrying
         anything outside [A-Za-z0-9_/-]. Both commits carry BREAKING CHANGE in
         their message; there is no CHANGELOG.md.
Why:     Harmless at `version = "0.0.0"` -- but the habit forms now, and the
         first published version inherits it.
Impact:  Someone upgrading finds the reason only in the git history.
Fix:     CHANGELOG.md in Keep-a-Changelog form; enter both.
```

### F3 🟡 Documentation — ARCHITECTURE describes a superseded state

```
File:    docs/ARCHITECTURE.md:5, :434, :584-585 (and .de.md correspondingly)
Problem: Three divergences, each verified:
         · Header: "eight stages complete -- 966 tests offline, 77 live reading"
           Actual: 1020 offline, 87 live, 75 writing
         · The roadmap table ends at stage 8; the metadata agent is a ninth
         · The module table lists neither `metadata_agent.py` nor
           `bapi/passthrough.py`. Counted: 0 occurrences of "Metadata Agent" in
           either language version
Why:     The document calls itself the project's plan. A plan that does not know
         two of its modules misleads.
Impact:  A newcomer concludes the metadata agent does not exist.
Fix:     Update header, roadmap table and module table, both languages.
```

### F4 🟡 Security — the traversal class is caught, not prevented

```
File:    src/edusharing/bapi/passthrough.py:146-159 (fixed) · src/edusharing/urls.py (path_segment)
Problem: On 29.08. a path traversal was found and fixed in `call()`:
         `path_segment` was applied to the provider but not to the route, and
         `call("../../administration/account")` reached the administration API
         with the X-API-KEY attached. It had been committed; review caught it.
Why:     A scanner written for this audit finds **0 of 60** interpolations
         unprotected today. But nothing stops the next one from being written
         unprotected -- there is no rule that enforces it.
Impact:  The class can recur, and in a library built for AI applications it is
         the most dangerous one, because the argument comes from a model.
Fix:     Adopt the scanner as a test case -- it runs offline and needs no
         instance. It exists in this audit as a tool, not yet as a guard.
```

### F5 🟡 Maintainability — `py.typed` without a type checker

```
File:    src/edusharing/py.typed · pyproject.toml (dependency-groups.dev)
Problem: The package ships `py.typed`, promising checked types. The dev group
         contains neither mypy nor pyright; CI runs ruff and pytest only.
Why:     Consumers point their own type checking at that promise. A wrong type
         here becomes an error there that nobody sees here.
Impact:  The assurance is uncovered.
Fix:     Either add mypy to the dev group and to CI, or drop `py.typed`. The
         first is right -- the annotations are present and consistent.
```

### F6 🟢 Maintainability — one complexity hotspot

```
File:    src/edusharing/flows/ranking.py:98  (_text_score)
Problem: Cyclomatic complexity 15 against a threshold of 10
         (`ruff --select C901`). The only hit in the project.
Why:     The function decides result ordering; changing it means holding 15
         branches in mind at once.
Impact:  Change risk, not misbehaviour.
Fix:     Extract the partial scores as functions; each becomes testable alone.
```

### F7 🟢 Security — two modules, two rules for logging URLs

```
File:    src/edusharing/transport.py:210 against src/edusharing/extraction.py:66
Problem: `extraction` deliberately logs only the host, never the URL, and says
         why: "a caller-chosen URL can carry a token in its query". `transport`
         logs the full URL at DEBUG, and again at INFO on a retry.
Why:     Measured 29.08.: edu-sharing's own URLs carry no token (`downloadUrl`
         has only `nodeId`; `preview` only `nodeId`/`storeId`), so this is
         harmless today. But `transport._resolve` accepts any absolute URL,
         including one from a foreign instance's response data.
Impact:  Conditional: an instance that hands out signed URLs would have them in
         the log at DEBUG. **Needs verification** -- no such instance was
         available, so this is not stated as fact.
Fix:     Either adopt `extraction`'s rule (host, not URL) or record in
         `transport` why it does not apply there.
```

### F8 🟢 Deployment — no CVE step in CI

```
File:    .github/workflows/ci.yml:44
Problem: The pipeline runs ruff and pytest. `pip-audit` runs nowhere
         automatically; today's run was by hand.
Why:     0 vulnerabilities across 48 dependencies today -- a point in time.
Impact:  A new CVE in httpx or attrs would surface only at the next manual run.
Fix:     Append a `pip-audit` step.
```

## 9. General observations

No file and line, therefore not findings:

- **The production run paid for itself and should recur.** It produced two real
  findings a single instance could never have shown: the withheld error messages
  (`security.logging.displayLevel`, measured 4 requests where staging needs 1)
  and a `content.text()` refused anonymously. A regular read-only run against a
  second instance is the most effective single testing measure this project has.
- **The skills registry is still undecided.** Of the four MCP tools from the
  earlier plan, topic pages and URL text are implemented and Wikipedia is
  explicitly excluded — the skills registry appears neither in the code nor in
  the exclusion list. Not a gap; an open decision.
- **No CONTRIBUTING.** For a project whose stated purpose is "reusable by third
  parties", the entry point for contributors is missing. Secondary while there
  is no remote.
