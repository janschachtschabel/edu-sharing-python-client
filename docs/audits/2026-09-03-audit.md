## 1. Executive summary

The library is in good shape for what it claims: every write reads back, every
id is encoded in one place, credentials never reach logs or exceptions, the
model-facing boundary flattens foreign text, and 1 303 offline tests at 99 %
line coverage run in under a minute. The two review rounds of 2026-09-02 left
no debris. What this audit adds are the classes of problem a diff review does
not see. **Top three risks:** (1) the transport re-sends non-idempotent writes
after a timeout or a 5xx, so one flaky second can create two nodes, two
comments or two proposals — in a library whose stated purpose is never to
misreport persistence; (2) a repository URL of the form `https://user:pw@host`
is accepted and then echoed into log lines, `repr`, exception URLs and every
viewer URL handed to a model; (3) the two documents a user or a model copies
from — REFERENCE and the skill — contain four calls that raise `TypeError`
as written, and the vendored 141 k-line generated layer cannot be reproduced
because its generator runs unpinned and its exit code is discarded. **The
single most important action:** make the retry loop method-aware (retry
connect failures for everything, read/write failures and 5xx only for
idempotent requests) — a one-afternoon change that closes the only way this
library can currently duplicate a write.

## 2. Overview

**Stack and purpose.** Python ≥ 3.11, async-first over `httpx`, with a
blocking mirror (`Repository` over `AsyncRepository`) and a generated
full-coverage layer from the edu-sharing 11.0 OpenAPI spec. It makes the
edu-sharing REST API usable by third parties and by AI tools: API-close objects
(`Node`, `SearchResult`, `Skills`), JSON-shaped flows (`repo.flows.*`), and a
model-context boundary (`agent/*`). Three neighbour services have clients of
their own (b-api LLM gateway, text extraction, metadata agent).

**What was read.** The whole hand-written layer, split across the four lenses
with overlap on `transport.py`, `nodes*.py`, `content.py`, `curate.py` and
`_sync.py`; the security, contract, sync-surface, tree, text, suggest,
duplicates and docs-guard tests; the six documentation files in both
languages, the changelog, the plans and the previous audits; the CI workflow,
packaging and the generator script. **Skipped:** the generated layer's
contents, the `openapi/` spec itself, and any live instance — the audit ran
offline; live behaviour is cited only where the code or a test records a
measurement.

**Numbers.** 1 303 offline tests pass in 45–65 s (32 s of that is one
documentation guard); coverage 99 % lines (4 326 statements, 55 missed);
`ruff` clean under the project's rules and clean of security-relevant leads
under the extended ones; `mypy --strict` clean; CI runs lint, types,
`pip-audit` and the suite on 3.11–3.14 and was green on the audited commit.

## 4. Verdict

**Conditional.** For reading — search, describe, placement, text, collections,
skills — the library is production-ready today: the boundaries hold, partial
answers are disclosed, and the behaviour is pinned by tests that would fail
before the fix. For **writing in automated pipelines** and for **model-facing
use** it is ready once four small conditions are met:

1. The retry loop stops re-sending non-idempotent requests after timeouts and
   5xx (COR-1) — until then a flaky second can duplicate a node, comment or
   proposal.
2. A repository URL with userinfo is refused or stripped into a credential
   (SEC-1) — until then a password can reach logs, tracebacks and hit URLs.
3. The four documented calls that raise are corrected and the guard learns to
   count positional slots (DOC-1, DOC-2) — until then a model following the
   skill cannot connect and a reader copying REFERENCE cannot create.
4. Downloads are bounded before parsing (SEC-2) — until then one model-chosen
   node id can pin memory and CPU.

None of the four is more than a day; together they are Phase 1 of §9.

## 6. All findings

Grouped by dimension, then severity. Findings that surfaced in more than one
lens are listed once with both angles. Line numbers refer to commit `fd5baa6`.

### Security

- **SEC-1 🟠 userinfo URL kept and leaked** — see §5.
- **SEC-2 🟡 unbounded download, quadratic parsers** — see §5.
- **SEC-3 🟡 `extraction.text_of` forwards URLs that `agent.safety` refuses** *(needs verification against the service)* — `src/edusharing/extraction.py` 222–231 (judges `urlsplit().hostname` only), 258–279 (`_judge`); the missing rule sits in `agent/safety.py` 83–84. `http://127.0.0.1\@example.com/` is judged as host `example.com` and forwarded verbatim; `http://user:pw@example.com/` is forwarded with the credentials to a third-party service; `agent.safety.is_safe_url` refuses both. A WHATWG parser behind `method="browser"` reads the first as host `127.0.0.1`. Fix: refuse `@` in the netloc and a backslash anywhere in `text_of`, sharing `agent.safety`'s reason function through `urls`; test in `test_extraction.py`.
- **SEC-4 🟡 an injected client with `follow_redirects=True` defeats the 3xx guard** — `src/edusharing/bapi/client.py` 136–178 (any client accepted), 526–531 (`X-API-KEY` per request); `transport.py` 103–128 checks `timeout`, not `follow_redirects`; `extraction.py` 149; `metadata_agent.py` 114. httpx keeps custom headers across cross-origin redirects, so a following client sends the key or a custom credential header wherever the gateway points (verified: the second request to another host carried the key). Fix: refuse `client.follow_redirects is True` at construction in all four clients, with the same wording as the `timeout` refusal.
- **SEC-5 🟢 server error text and suggestion labels reach the model context without `one_line`** — `agent/result.py` 64–73, `agent/format.py` 136–137 with `results.py` 155–159. Verified: a label or message containing a newline plus `id: …` produces a second record line; exploitability low (vocabulary is admin-controlled). Fix: `one_line()` at both sites.
- **SEC-6 🟢 the redirect error message embeds the `Location` header verbatim** — `transport.py` 246–261. A presigned link lands in `str(exc)`, logs and tool text. Fix: report the host, keep the full value as `exc.location`.
- **SEC-7 🟢 `mimetype` interpolated unescaped into multipart part headers** — `content.py` 134–143, 171–176. httpx 0.28.1 writes `Content-Type: <mimetype>` without escaping CR/LF (verified); injection into the caller's own part only. Fix: validate against a `type/subtype` token regex.
- **SEC-8 🟢 A11 and parameter validation not propagated to the sibling clients** — `extraction.py` 133–149 (`timeout` validated then discarded with a client; `backoff_base` never validated — `-1`, `nan` accepted), `metadata_agent.py` 105–114, `bapi/client.py` 156–177. Fix: the transport's refusal and `at_least("backoff_base", …)` in the three constructors.
- **SEC-9 🟢 closures of 2026-08-28 spot-checked** — A2 (label defuse, `agent/sanitize.py` 88–121, pinned by `test_agent_sanitize.py` 90–107), A5 (`auth.py` 154–176 reports length and shape only), A7 (`urls.py` 74–118 refuses decimal, hex, octal, shortened and IPv4-mapped forms — verified on 3.13; *needs verification on 3.11/3.12 for the mapped forms*) are closed. Clean surfaces: no `verify=False`, https default, timeouts on all four clients, `json` only (no pickle/eval/yaml/subprocess), credential scope by prefix and boundary, every id through `path_segment` with an AST guard, headers never logged, `.env` never committed, Java stack traces kept as attributes, ACL writes merge rather than replace.

### Logic & Correctness

- **COR-1 🟠 non-idempotent writes re-sent** — see §5.
- **COR-2 🟠 `search_in_collection` folds every failure into `unreadable`** — see §5.
- **COR-3 🟡 read-back by content equality accepts a pre-existing identical record** — `comments.py` 106–109 (`Comments.add` returns the newest comment whose `text == text`), `workflow.py` 141–143 (`Workflow.submit` matches status and receivers). Verified offline: with the server dropping the PUT, `add("+1")` returned an older `+1` by another author and `submit` returned the older step instead of raising `SilentDropError`. Fix: snapshot ids/timestamps before the write and require a record that was not there before.
- **COR-4 🟡 `Repository.__init__` leaks a running loop thread when construction fails; `close()` after a join timeout** — `repository.py` 329–332, `_sync.py` 36–59. `LoopThread()` starts before `AsyncRepository(url, **kwargs)`; a raising constructor (bad URL, `timeout` plus `client`) leaves the thread alive — verified: three failed constructions, three live `edusharing-loop` threads. No `__del__`/`weakref.finalize`. `LoopThread.close()` calls `loop.close()` even when `join(timeout=5)` timed out, which raises on a running loop *(needs verification)*. Fix: build the async repository first (or close the loop in `except`), add `weakref.finalize`, cancel pending tasks and guard `loop.close()`.
- **COR-5 🟡 created id lost on a later failure** — see §5.
- **COR-6 🟡 `Vocabulary.clear_cache()` during an in-flight fetch re-inserts stale values** — `vocab.py` 108–114, 174–182. Verified offline: a fetch started, `clear_cache()` mid-flight, the completed fetch wrote the old values into the cleared cache. Fix: a generation counter checked before storing.
- **COR-7 🟢 `check()` demands exact list equality** *(needs verification against server normalisation)* — `nodes_write.py` 105–108. A repository that reorders multi-valued properties, trims whitespace or normalises dates would raise a false `SilentDropError`; no live test writes such a property. Fix: compare as multisets of stripped strings, or document the strictness.
- **COR-8 🟢 keyword merge writes empty or padded keywords as-is** — `nodes_write.py` 204–211; verified `add_keywords("", "   ", " Optik ")` sent `['Physik', '', ' Optik ']`. Fix: skip blanks, store `k.strip()`.
- **COR-9 🟢 falsy scalars read as absent** — `nodes.py` 177–182 (`Node.get`), `results.py` 191–195 (`_first`) return `None` for a scalar `0`/`False`, while `flows/serialize.py` 58–62 now keeps them. Fix: one rule (`is None or == []`) in both helpers.
- **COR-10 🟢 a child's `CancelledError` becomes a failed leg** — `collections.py` 128–147, `flows/rerank.py` 123–126 treat every `BaseException` from `gather(return_exceptions=True)` as partial; `search_all` and `placement` already re-raise non-`EduSharingError`. Fix: the same rule.
- **COR-11 🟢 `collections.update(description="")` may raise a false `SilentDropError`** *(needs verification)* — `collections.py` 320–334: `""` is sent, read back through `Node.get` which returns `None` for an empty property. Fix: compare `(stored or "") != description`.

### API

- **API-1 🟡 `json.JSONDecodeError` escapes the `EduSharingError` contract** — `transport.py` 285–288 (`json`), `bapi/client.py` 536–537, `metadata_agent.py` 293–296, `extraction.py` 303–304 and 361–366 (a 3xx becomes `"no_text"`). ### Architecture

- **ARC-1 🟠 layering inversion** — see §5.
- **ARC-2 🟡 three retry loops, three policies, no jitter** — `transport.py` 223–283, `extraction.py` 289–311, `bapi/client.py` 520–548. Transport retries `ServerError` by type; the two others retry `{429, 500, 502, 503, 504}` by status; all use deterministic `base·2^n` under an 8-wide semaphore. Fix: one `retry.py` policy object (retryable, budget, backoff, jitter, `Retry-After`) shared by the three, with the transport keeping its type-based classification — and the idempotency rule of COR-1.
- **ARC-3 🟡 import cycles held open by five local imports and 29 `TYPE_CHECKING` blocks** — `placement.py` 87, 136; `childobjects.py` 77, 137; `skills.py` 278. ### Performance
