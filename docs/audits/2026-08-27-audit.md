# Audit — edu-sharing-python-client

Date: 2026-08-27 · Depth: **Standard** (all applicable dimensions) ·
Auditor's note: this audit was performed by the author of the code. That is a
known weakness — findings were therefore verified by execution wherever
possible, not by reading alone.

---

## 1. Executive summary

The library is in good shape on correctness and testing: 364 offline tests, 42
live tests against a real instance, 97 % coverage of the hand-written layer, and
an unusual amount of measured behaviour encoded rather than assumed. **One
critical security finding blocks production use in the very scenario the library
was built for.** URL path segments — node ids, collection ids, metadata-set names
— are interpolated into request paths without encoding, at 16 sites. A node id of
`../../../admin/v1/applications` reaches a different endpoint, verified by
execution. In an MCP server the node id comes from the language model, i.e. from
foreign data. **The single most important action: percent-encode every path
segment in the transport layer.**

Beyond that, the gaps are operational rather than structural: no CI, no logging,
no `py.typed`.

## 4. Verdict

**Conditional.** Ready for use as a scripting and curation library today. **Not**
ready to sit behind an MCP server or any service that accepts identifiers from
untrusted input until F1 is fixed — that is precisely the scenario
`edusharing.agent` exists for, so the gap sits where it hurts most.

Conditions for "production-ready":

1. F1 (path encoding) fixed and covered by a test.
2. F2 (`assert` in production path) and F3 (missing parameter validation) fixed.
3. F4 (`py.typed`) added — a typed library that ships no type information is
   half a library.

## 5. Top issues

### F1 🔴 Security — path segments interpolated without encoding

```
File:     src/edusharing/nodes.py (and 15 further sites)
Lines:    174, 203, 211, 290, 356, 396; collections.py 148, 203, 228, 241;
          content.py 116, 154; search.py 155; vocab.py 164; bapi/client.py 152, 193
Problem:  Node ids, collection ids, parent ids and metadata-set names are placed
          into URL paths via f-strings. No site calls urllib.parse.quote.
Why:      A value containing "/", "..", "?" or "#" changes the path, the query
          or both. The library sends the request with the service's own
          credentials.
Impact:   Verified by execution against a mock transport:
            "../../../admin/v1/applications"
              -> /rest/node/admin/v1/applications/metadata
            "abc?admin=1"
              -> /rest/node/v1/nodes/-home-/abc?propertyFilter=-all-
                 (the "/metadata" suffix is swallowed entirely)
            "abc#frag"
              -> the fragment splits the URL
          In an MCP server the node id comes from the language model, hence from
          foreign content. This is the same class of problem as SSRF — which the
          library guards against for external URLs (agent/safety.py) but not for
          its own paths.
Fix:      Encode in one place, in the transport, so no call site can forget it.
Example:
          # transport.py
          from urllib.parse import quote

          def path_segment(value: str) -> str:
              """Percent-encode one path segment. safe="" so that "/" is
              encoded too -- a segment must never span path boundaries."""
              return quote(str(value), safe="")

          # nodes.py
          f"/node/v1/nodes/-home-/{path_segment(self.id)}/metadata"
```

### F2 🟠 Correctness — `assert` in a production path

```
File:     src/edusharing/bapi/client.py
Lines:    256
Problem:  "assert last is not None" guards the final raise of the retry loop.
Why:      Under "python -O" assertions are stripped. The next line then executes
          "raise None", which raises TypeError instead of the actual error.
Impact:   Anyone running with -O (common in containers) gets "exceptions must
          derive from BaseException" instead of the b-api's message. The real
          cause is lost exactly when it is needed.
Fix:      The solution already exists in this repository -- copy it.
          transport.py:186 states the invariant in a comment instead of
          asserting it, backed by the constructor check at transport.py:77
          (_at_least("max_retries", max_retries, 0)). The inconsistency IS the
          finding: of the two retry loops, one was fixed and the other was not.
```

### F3 🟠 Correctness — b-api client validates no parameters

```
File:     src/edusharing/bapi/client.py
Lines:    81-112 (__init__)
Problem:  Only api_key is checked. max_retries, max_concurrency, timeout and
          backoff_base are taken unvalidated, unlike Transport (transport.py:76-79).
Why:      max_retries=-1 makes range(0) empty, the loop never runs, and execution
          reaches exactly the assert of F2.
Impact:   A configuration error surfaces as an incomprehensible TypeError rather
          than as a message naming the parameter.
Fix:      Reuse transport._at_least; move it to a shared place, or call it here.
```

### F4 🟠 Packaging — no `py.typed` marker

```
File:     src/edusharing/ (missing file)
Problem:  Every module is fully type-annotated, but the package ships no
          py.typed marker (PEP 561).
Why:      Without it, mypy and pyright ignore the annotations in installed
          copies and treat the whole library as untyped.
Impact:   Users get no type checking, no completion from the annotations. For a
          library whose selling point is clarity, the work is done and invisible.
Fix:      Create an empty src/edusharing/py.typed and add to pyproject.toml:
            [tool.hatch.build.targets.wheel]
            packages = ["src/edusharing"]
            # plus ensure py.typed is included in the wheel
```

### F5 🟡 Ops — no logging anywhere in the library

```
File:     entire src/edusharing (no import logging)
Problem:  The library emits nothing: no request, no retry, no model fallback.
Why:      A service using it cannot reconstruct what happened. The b-api client
          silently tries up to three models (client.py:198-215); which one
          answered is only in last_model, and why the others failed is nowhere.
Impact:   Incident analysis in production is guesswork.
Fix:      logging.getLogger("edusharing") with DEBUG for requests and INFO for
          retries and fallbacks. Never log credentials -- BasicCredential
          already hides them in repr, that discipline must hold in logs too.
```

### F6 🟡 Performance — lock dictionary grows unbounded

```
File:     src/edusharing/vocab.py
Lines:    81 (_locks), 153-155 (clear_cache)
Problem:  _locks gains an entry per (property, locale) and is never cleaned;
          clear_cache() empties _cache but not _locks.
Why:      A long-running service (an MCP server) that resolves many properties
          across several locales accumulates lock objects indefinitely.
Impact:   Small but unbounded memory growth; clear_cache() does not do what its
          name promises.
Fix:      Clear _locks in clear_cache() as well. The growth itself is bounded in
          practice by the number of properties, so this is hygiene rather than a
          leak -- but the half-clearing is a genuine inconsistency.
```

### F7 🟡 Ops — `.coverage` is tracked in the repository

```
File:     .coverage (tracked), .gitignore (missing entry)
Problem:  The coverage database is committed. .gitignore covers .pytest_cache
          and .ruff_cache but not .coverage.
Impact:   Binary churn in every diff; the file is machine- and run-specific.
Fix:      git rm --cached .coverage and add ".coverage" plus "htmlcov/" to
          .gitignore.
```

### F8 🟡 Ops — no CI

```
File:     (no .github/workflows, no tox.ini, no Makefile)
Problem:  Tests, linting and the generator pipeline run only locally.
Why:      Every guarantee this library makes -- read-back checks, mutation-tested
          boundaries, 97 % coverage -- depends on someone remembering to run
          pytest.
Impact:   A regression reaches main unnoticed. The offline suite takes 4 seconds;
          there is no cost argument against automating it.
Fix:      A GitHub Actions workflow running "uv run pytest -q" and
          "uv run ruff check" on push. The live and write suites must NOT run in
          CI -- they need credentials and write to a real instance.
```

### F9 🟢 Dependencies — dev dependencies declared twice

```
File:     pyproject.toml
Lines:    25 ([project.optional-dependencies] dev), 78 ([dependency-groups] dev)
Problem:  pytest, ruff and openapi-python-client sit in optional-dependencies;
          pytest-cov landed in dependency-groups when added via "uv add --dev".
Impact:   "pip install -e .[dev]" gives a different set than "uv sync"; a
          contributor without uv is missing pytest-cov.
Fix:      Consolidate into one place. dependency-groups (PEP 735) is the more
          modern choice, but consistency matters more than which one.
```

### F10 🟢 Documentation — German remnants in package metadata

```
File:     pyproject.toml
Lines:    4 (description), 19, 57, 72-73 (comments)
Problem:  After the changeover to English, the package description is still
          German: "Python-Bibliothek fuer edu-sharing-Repositorien ...".
Impact:   That string is what PyPI shows as the one-line summary.
Fix:      Translate description and the four comments.
```

| Category | Present | Effort | Risk if unfixed | Compounding? |
|---|---|---|---|---|
| **Security debt** | F1 (path encoding) | small (<1 day) | **critical** — blocks the intended use case | No, but it blocks adoption |
| **Architecture debt** | two modules above threshold | small | low | Slightly — the next feature makes the split harder |
| **Test debt** | none material; live coverage of a foreign instance missing | medium | medium | No |
| **Dependency debt** | F9 (double declaration) | small | low | Yes — grows with each new dev dependency |
| **Documentation debt** | F10, no CHANGELOG/CONTRIBUTING | small | low | No |
| **Infrastructure debt** | F5 (logging), F8 (CI) | medium | **high** | **Yes** — without CI, every future guarantee rests on manual discipline |

**The compounding debt is infrastructure.** The library's value rests on measured
guarantees; without CI, every one of them decays silently the moment someone
forgets to run the suite. That, not the code, is the thing that gets worse with
time.

## 9. Refactoring roadmap

**Phase 1 — blockers (under one week)**

1. **Encode path segments** (F1). One helper in the transport, applied at all 16
   sites, plus tests for `..`, `?` and `#`. Comes first because it blocks the
   intended use case. *Effort: small. Improves: security.*
2. **b-api client: validate parameters, drop the `assert`** (F2, F3). Comes
   second because it is the same class of fix already applied to the transport,
   and the inconsistency is what allowed it to survive. *Effort: small. Improves:
   correctness.*
3. **Ship `py.typed`** (F4). *Effort: minutes. Improves: packaging, usability.*

**Phase 2 — foundations (one to two weeks)**

4. **Set up CI** (F8). Offline suite plus ruff on every push; live suites
   explicitly excluded. Comes here because everything afterwards relies on it.
   *Effort: small. Improves: ops, testing.*
5. **Introduce logging** (F5). Requests at DEBUG, retries and model fallbacks at
   INFO, never credentials. *Effort: medium. Improves: ops.*
6. **Housekeeping** (F6, F7, F9, F10) — the quick wins above, in one commit each.
   *Effort: small. Improves: dependencies, documentation, performance.*

**Phase 3 — proving the central claim (as access allows)**

7. **Verify against a foreign instance.** The genericity claim is the library's
   reason for existing and is the least evidenced part of it. Either credentials
   for `stable.demo.edu-sharing.net` or another reachable instance.
   *Effort: medium. Improves: testing, credibility.*

**Phase 4 — before publishing**

8. Real version number, CHANGELOG, CONTRIBUTING, and a decision on whether the
   German test docstrings stay.
